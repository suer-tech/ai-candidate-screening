## Why

Текущий candidate pipeline передаёт итоговой модели сокращённый набор предварительно извлечённых фактов и не гарантирует проверку каждого требования вакансии, полный контекст доказательств, глобальный поиск конфликтов и независимую семантическую верификацию. Нужен единый исполняемый контракт оценки — неизменяемая матрица конкретной версии профиля, которая одинаково направляет анализ всех сопоставимых кандидатов.

## What Changes

- Добавить ленивую LLM-компиляцию одной неизменяемой матрицы при старте первого кандидата по `profileVersion`, с атомарным claim/lock, checksum и переиспользованием всеми последующими кандидатами этой версии.
- Добавить один независимый LLM-вызов критика-редактора: он проверяет draft в чистом контексте и возвращает окончательную полную матрицу, при необходимости сразу внося исправления. Повторная критика и отдельный repair-loop не блокируют обработку кандидата.
- Сохранить явное утверждение HR самого профиля вакансии, но разрешить в утверждённом профиле качественные формулировки, которые матричный компилятор интерпретирует без выдумывания числовых порогов или кадровых правил.
- Заменить одношаговое извлечение «фактов» на направляемое матрицей извлечение source claims, полный контекст доказательств, глобальный evidence graph и межпакетный поиск конфликтов.
- Требовать отдельный результат по каждой строке матрицы, вложенную проверку всех условий A/B/C, независимую верификацию decision-driving строк и детерминированную итоговую рекомендацию.
- Поручить LLM-компилятору определять `required` из семантики существующих критериев профиля без отдельного пользовательского раздела; использовать `hardRequired` только для критериев, происходящих из раздела стоп-факторов.
- Разрешить отказ не только по подтверждённому стоп-фактору, но и по доказанному несоответствию `required` либо по существенному отрицательному сигналу вне матрицы, если его критичность и доказательства независимо подтверждены отдельной LLM-проверкой.
- Запретить неизвестной роли спикера, низкоуверенному фрагменту, prompt injection и чувствительным нерелевантным признакам становиться единственным либо допустимым основанием кадрового вывода.
- Сохранять непредусмотренные сигналы информационными по умолчанию, но разрешить отдельному bounded risk-assessment и независимой проверке повысить доказанный существенный сигнал до `criticalUnmappedRisk`, влияющего на рекомендацию.
- Сохранить старые результаты неизменными и развернуть новый workflow поэтапно через shadow mode и feature flag; автоматический пересчёт завершённых или активных старых запусков запрещён.
- **BREAKING** Уточнить доказательность ABC: один допустимый фрагмент остаётся минимально необходимым, но больше не является автоматически достаточным, если не покрывает определяющие условия уровня матрицы.

## Capabilities

### New Capabilities

- `matrix-driven-assessment`: Контракт матрицы версии вакансии, её ленивой компиляции, критики, фиксации, заполнения и bounded agent workflow.

### Modified Capabilities

- `vacancy-profile`: Разрешить утверждённые качественные требования, передать LLM определение requiredness, связать `hardRequired` только со стоп-факторами и отделить утверждение профиля от автоматической компиляции матрицы.
- `candidate-workflow`: Включить ленивую shared-компиляцию матрицы и поэтапный matrix-driven pipeline в жизненный цикл запуска.
- `assessment-and-evidence`: Уточнить claims/facts, достаточность ABC, глобальные конфликты, чувствительные данные, полное покрытие критериев, independently verified critical unmapped risks и формулу рекомендации.
- `reporting-and-notifications`: Показывать заполненную матрицу, interpretation notes, пробелы, конфликты и полную provenance нового workflow без изменения двухфайлового пользовательского контракта.
- `integrations-and-operations`: Добавить versioned LLM skills/capabilities, budgets, timeout/repair policy, защищённые traces и rollout routing.
- `data-and-security`: Зафиксировать неизменяемые matrix artifacts, разграничение матрицы по профилю и минимизацию чувствительных данных в decision context.
- `quality-gates`: Добавить независимый ATDD, shadow-quality gates и обязательный регрессионный контур для нового workflow.

## Impact

- PostgreSQL schema и repositories для matrix artifacts, compilation attempts, criterion trees, candidate rows, claims, conflicts и provenance.
- `web/server/llm/` для versioned compiler/critic-editor/extraction/evaluation skills и response schemas.
- `web/server/agent-runtime/` и `web/server/candidate-pipeline/` для bounded DAG, shared compilation, evidence graph, validation и feature-flagged cutover.
- Assessment snapshots, report projection, operational metrics, protected traces и обязательные acceptance/E2E fixtures.
- Существующие profile versions, активные legacy-запуски и готовые результаты не мигрируются и не пересчитываются автоматически.
