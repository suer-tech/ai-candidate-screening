## Why

Компактный HR-отчёт также должен повторять практическую навигацию из согласованного образца: имена исходных резюме, видео, стенограммы и рекомендаций там являются кликабельными ссылками на конкретные файлы Google Drive/Docs. Без этого единый PDF теряет роль рабочей HR-точки входа в материалы.

Матрица нужна прежде всего для гарантированного обхода каждого параметра вакансии, однако текущий workflow превратил её в чрезмерно строгий evidence-аудит: самоописание кандидата обесценивается, положительные выводы гасятся повторными проверками, а риск-ориентированный каскад доминирует над сильными сторонами. Нужен coverage-first workflow, пригодный для реальной HR-работы и всегда доводящий кандидата до результата.

## What Changes

- Компилировать компактную матрицу как точную структуризацию содержательных пунктов уже утверждённого профиля: один смысловой пункт — одна строка, без новых требований, дробления по словам и скрытого усиления смысла.
- Оставить один fail-soft critic-editor матрицы, который проверяет только полноту, верность источнику, отсутствие выдуманных требований, чрезмерного дробления и ошибочной классификации явных стоп-факторов; отсутствие ответа критика не блокирует обработку.
- Считать резюме, ответы кандидата на интервью и предоставленные документы допустимыми первичными HR-источниками. Происхождение сведения сохраняется для объяснимости, но отсутствие внешнего подтверждения не означает `Недостаточно данных`.
- Делить стенограмму по токенному бюджету с overlap вопроса/ответа. Каждый batch MUST только извлекать сведения и возвращать coverage entry для каждого переданного `criterionId`; batch MUST NOT назначать итоговый статус кандидата.
- Добавить deterministic coverage harness для точного совпадения requested/returned criterion IDs, точечного повтора пропущенных ID и одного gap-search по критериям без найденных сведений.
- После объединения всех batch/document claims оценивать каждый критерий ровно один раз одним из трёх состояний: `Соответствует`, `Не соответствует`, `Недостаточно данных`.
- Сохранять реальные межисточниковые противоречия, но не считать конфликтом дополнение, разную детализацию, разные периоды, отсутствие упоминания или явное последующее исправление.
- Заменить отрицательно ориентированный unmapped-risk cascade сбалансированным поиском дополнительных `STRENGTH`, `CONCERN` и `QUESTION`; дополнительные наблюдения не меняют матрицу и не принимают решение самостоятельно.
- Ограничить повторную семантическую проверку подтверждёнными стоп-факторами и существенно отказными выводами; проверяющий получает точные цитаты, исправляет вывод один раз и при отсутствии ответа не отменяет исходную строку.
- Отказаться от автоматического понижения строки из-за отсутствия независимого источника, строгого полного покрытия ABC и детерминированного отказа по любому LLM-классифицированному `required`.
- Сохранить единственное безусловное кадровое правило: подтверждённый стоп-фактор всегда даёт `Не рекомендовать`. Остальную рекомендацию формирует итоговая LLM по совокупности строк, сильных сторон, существенных несоответствий и дополнительных наблюдений.
- Формировать сильные стороны, компетенции, вопросы и ограничения непосредственно из заполненных строк; техническая ошибка вспомогательной стадии MUST NOT останавливать отчёт.
- Ввести отдельную coverage-first compatibility identity: ручной recovery переиспользует успешные checkpoints только при точном совпадении input/profile/workflow/policy/artifact contract, а compact matrix публикуется отдельно от ранее созданной matrix-v2 той же версии профиля.
- Сделать каждую итоговую строку доказательной: решение и вывод модели сопровождаются точной цитатой и разрешённым locator исходного резюме, интервью, рекомендации или документа; derived strengths, competencies, risks и recommendation не могут существовать без ссылки на такие строки.
- Разделить внутренний audit и HR-представление: технические claim/artifact/criterion IDs остаются в provenance, а веб и PDF показывают название критерия, решение, понятное основание, цитату и человекочитаемое место источника без сообщений внутренних критиков.
- Оценивать ABC только по заполненным A/B/C-направлениям вакансии; незаполненный ABC-профиль явно отображается как не настроенный и не подменяется строками основной матрицы.
- Заменить два пользовательских PDF одним компактным HR-отчётом по принятому образцу: кандидат и вакансия; исходные материалы; организационные моменты; ревью; ключевые доказательства; ABC по направлениям; технический чек; мотивация и соответствие роли; риски; решение; финальное HR-резюме.
- Не публиковать в компактном PDF отдельные технические разделы `Критерии вакансии`, `Матрица оценки`, `Стоп-факторы`, `Вопросы`, внутренние provenance/ID или повторяющий recommendation callout. Полная матрица остаётся доступной в веб-интерфейсе и audit artifacts, а её существенные выводы входят в ревью, доказательства, риски и решение.
- Добавить один ограниченный report-composer, который получает только итоговые структурированные artifacts, не меняет рекомендацию/ABC/статусы строк и связывает каждое содержательное утверждение с существующими evidence. Ошибка composer MUST приводить к детерминированной сборке того же одного отчёта, а не к падению кандидата.
- Согласовать immutable guard новых candidate-scoped matrix-таблиц с нормативным удалением кандидата: прямые изменения остаются запрещены, а repository-controlled cascade разрешается только внутри точного transaction-local cleanup scope.

## Capabilities

### New Capabilities

- `matrix-driven-assessment`: Coverage-first матрица вакансии, batch coverage ledger, попунктная оценка и fail-soft завершение кандидата.

### Modified Capabilities

- `vacancy-profile`: Матрица точно структурирует исходные пункты без расширения и обязательности, придуманной системой.
- `candidate-workflow`: Батчи только извлекают сведения; единая оценка выполняется после глобального объединения.
- `assessment-and-evidence`: HR-источники допустимы сами по себе; проверка объясняет, а не разрешает вывод; рекомендация становится целостной.
- `reporting-and-notifications`: Положительные строки питают сильные стороны и компетенции, пробелы становятся вопросами; новые обработки публикуют один цельный HR-отчёт вместо пары PDF.
- `integrations-and-operations`: Версионируемые prompts/schemas для coverage extraction, gap-search, row evaluation и fail-soft checks.
- `data-and-security`: Candidate-scoped claims и locators сохраняются без межкандидатного смешивания.
- `quality-gates`: Независимый ATDD проверяет coverage ledger, отсутствие пропусков и отсутствие блокирующего критического каскада.

## Impact

- `web/server/llm/artifacts.ts` и response schemas для compiler/critic, batch extraction, balanced observations и row evaluation.
- `web/server/candidate-pipeline/production-runtime.ts`, batching/aggregation helpers и matrix domain contracts.
- Assessment/report projection, чтобы положительные строки заполняли competencies, strengths, ABC и access-to-KE вместо пустых массивов.
- Active matrix-v2 artifacts остаются versioned; новые candidate runs используют обновлённую workflow/prompt identity без изменения старых опубликованных результатов.
- Новые coverage-first runs фиксируют `matrix-v3`; прежние `matrix-v2` runs и vacancy matrices остаются читаемыми, но не являются recovery source для `matrix-v3`.
- Старые пары отчётов остаются читаемыми; новый report artifact и пользовательская публикация содержат ровно один PDF на версию анализа.
