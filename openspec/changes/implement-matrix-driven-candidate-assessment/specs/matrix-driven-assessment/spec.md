## Purpose

Гарантирует полный попунктный обход параметров вакансии при оценке кандидата без добавления скрытых требований и без обесценивания обычных HR-источников.

## ADDED Requirements

### Requirement: MDA-001 Ленивая матрица версии вакансии
При старте первого кандидата по зафиксированной `profileVersion` система MUST автоматически скомпилировать ровно одну матрицу до анализа материалов кандидата. Материалы кандидата MUST NOT влиять на состав матрицы. Последующие запуски той же версии MUST переиспользовать опубликованный artifact и checksum.

#### Scenario: Первый кандидат запускает компиляцию
- **WHEN** для `profileVersion` ещё нет опубликованной матрицы
- **THEN** система компилирует и публикует её до candidate evidence extraction

#### Scenario: Следующий кандидат использует ту же матрицу
- **WHEN** матрица версии уже опубликована
- **THEN** новая компиляция не выполняется и checksum совпадает

### Requirement: MDA-002 Компактная верность исходному профилю
Матрица MUST содержать одну строку на каждый самостоятельный содержательный пункт заполненных разделов профиля с исходным section, точным sourceRef/sourceText и нейтральной интерпретацией. Компилятор MUST NOT добавлять требования, числовые пороги, способы доказательства или кадровые правила, которых нет в профиле, и MUST NOT дробить один пункт по каждому слову, примеру или ожидаемому доказательству. Явный список независимых пунктов MAY стать несколькими строками; тесно связанная формулировка одного результата MUST оставаться одной строкой.

#### Scenario: Один смысловой пункт содержит несколько поясняющих примеров
- **WHEN** профиль описывает требование и затем перечисляет примеры его проявления
- **THEN** система создаёт одну строку, а примеры сохраняет как контекст интерпретации

#### Scenario: В профиле есть отдельные маркированные требования
- **WHEN** раздел содержит несколько самостоятельных пунктов
- **THEN** каждый пункт представлен ровно одной строкой в исходном порядке

#### Scenario: Профиль содержит качественную формулировку
- **WHEN** HR написал качественное требование без числового порога
- **THEN** модель сохраняет best-effort нейтральную интерпретацию без придуманного порога

### Requirement: MDA-003 Один fail-soft critic-editor матрицы
Критик MUST вызываться не более одного раза и MUST проверять только покрытие исходных пунктов, верность sourceRefs/sourceText, отсутствие новых требований, чрезмерного дробления, смыслового усиления и ошибочной классификации явного стоп-фактора. При ясной ошибке критик MUST вернуть полный исправленный successor; при отсутствии замечаний — исходный draft. Timeout, пустой ответ или остаточная неоднозначность MUST NOT блокировать кандидата: технически пригодный draft компилятора публикуется как fallback.

#### Scenario: Критик находит чрезмерное дробление
- **WHEN** один исходный пункт превращён в несколько искусственных строк
- **THEN** critic-editor объединяет их в один полный successor

#### Scenario: Критик недоступен
- **WHEN** compiler draft технически пригоден, а critic call завершился timeout или без результата
- **THEN** система публикует draft и продолжает обработку с warning provenance

### Requirement: MDA-004 Batch coverage ledger
Каждый transcript/document batch MUST получать явный список `requestedCriterionIds` и MUST возвращать ровно одну coverage entry для каждого ID со значением `FOUND` либо `NOT_FOUND_IN_BATCH`. Batch MUST только извлекать `SUPPORTS`, `CONTRADICTS` и `CONTEXT` сведения с точными locators и MUST NOT назначать итоговый статус критерия. Deterministic harness MUST отклонять пропущенные, дублированные и неизвестные IDs и выполнять точечный повтор только для пропущенных IDs.

#### Scenario: В batch нет сведений по критерию
- **WHEN** критерий был просмотрен, но релевантный фрагмент отсутствует
- **THEN** entry равна `NOT_FOUND_IN_BATCH` и не означает несоответствие кандидата

#### Scenario: Модель пропустила ID в structured output
- **WHEN** returned IDs не совпадают с requested IDs
- **THEN** harness повторно отправляет только отсутствующие IDs и не повторяет весь batch

#### Scenario: Overlap дублирует реплику
- **WHEN** один utterance попал в два соседних batches
- **THEN** сведения дедуплицируются по criterionId, utterance/locator и relation

### Requirement: MDA-005 Один gap-search для пустых критериев
После первичного объединения система MUST определить критерии без единого найденного сведения во всех материалах и MUST выполнить один bounded gap-search только по ним. Gap-search MUST искать упущенные фрагменты, но MUST NOT оценивать кандидата или вводить новые критерии.

#### Scenario: Первичный проход ничего не нашёл
- **WHEN** все coverage entries критерия равны `NOT_FOUND_IN_BATCH`
- **THEN** критерий включается в один точечный gap-search

#### Scenario: Gap-search также пуст
- **WHEN** повторный поиск не находит содержательного сведения
- **THEN** итоговый evaluator MAY поставить `Недостаточно данных`

### Requirement: MDA-006 Полное однократное заполнение матрицы кандидата
После объединения всех материалов каждый `criterionId` MUST быть оценён ровно один раз состоянием `Соответствует`, `Не соответствует` либо `Недостаточно данных` с reason, supporting/contradicting evidence IDs и вопросом при нехватке данных. Evaluation harness MUST проверять точное равенство matrix IDs и returned row IDs; пропуски MUST получать точечный retry. Технический сбой после bounded retry MUST создавать явно маркированную строку `Недостаточно данных` и MUST NOT останавливать отчёт.

#### Scenario: Все строки возвращены
- **WHEN** evaluator возвращает точный набор matrix IDs
- **THEN** результат принимается без дополнительной семантической критики

#### Scenario: Одна строка отсутствует
- **WHEN** evaluator пропустил один criterionId
- **THEN** система повторно оценивает только этот criterionId

#### Scenario: Точечный retry неуспешен
- **WHEN** строку не удалось получить после bounded retry
- **THEN** система создаёт технически маркированное `Недостаточно данных` и продолжает к отчёту

### Requirement: MDA-007 Мягкая проверка высокорисковых выводов
Дополнительная семантическая проверка MAY выполняться только для подтверждённого срабатывания стоп-фактора и существенно отказного вывода. Проверяющий MUST получать исходный критерий и точные цитаты обеих сторон, MUST возвращать полный исправленный вывод за один вызов и MUST NOT требовать независимого внешнего источника. Отсутствующий, пустой или неуспешный ответ проверяющего MUST означать сохранение исходного вывода, а не его понижение.

#### Scenario: Проверяется стоп-фактор
- **WHEN** evaluator считает явный стоп-фактор сработавшим
- **THEN** проверяющий видит точные цитаты и либо сохраняет, либо один раз исправляет вывод

#### Scenario: Проверяющий не вернул решение
- **WHEN** verification output не содержит решения по строке
- **THEN** исходная строка остаётся неизменной и обработка продолжается

### Requirement: MDA-008 Сбалансированный open pass и итоговая рекомендация
Open pass MUST искать дополнительные `STRENGTH`, `CONCERN` и `QUESTION`, не изменяя shared matrix и не принимая рекомендацию. Подтверждённый явный стоп-фактор MUST всегда вести к `Не рекомендовать`; остальные дополнительные наблюдения MUST передаваться единой итоговой LLM вместе со всеми строками для целостной рекомендации.

#### Scenario: Open pass находит только сильную сторону
- **WHEN** дополнительное наблюдение имеет тип `STRENGTH`
- **THEN** оно показывается в сильных сторонах и не создаёт нового критерия

#### Scenario: Open pass находит существенную проблему
- **WHEN** дополнительное наблюдение имеет тип `CONCERN`
- **THEN** итоговая LLM учитывает его вместе со всей матрицей и объясняет влияние на рекомендацию

### Requirement: MDA-009 Версионированная identity shared matrix
Shared vacancy matrix MUST адресоваться сочетанием точной `profileVersion` и matrix workflow/compiler compatibility identity. Публикация новой compatibility identity MUST создавать новый immutable matrix artifact и MUST NOT перезаписывать либо переиспользовать матрицу прежней identity. Все кандидаты одной profile/workflow identity MUST продолжать переиспользовать один checksum.

#### Scenario: Для профиля уже есть старая матрица
- **WHEN** существует опубликованная `matrix-v2`, а новый run использует `matrix-v3`
- **THEN** система лениво компилирует отдельную compact `matrix-v3` и сохраняет обе immutable версии

#### Scenario: Повтор внутри matrix-v3
- **WHEN** другой кандидат использует ту же `profileVersion` и `matrix-v3`
- **THEN** он получает тот же matrix artifact и checksum без новой компиляции

### Requirement: MDA-010 Доказательная итоговая строка
Evaluator MUST возвращать для каждого критерия решение, понятный вывод и массив evidence. Каждый evidence MUST содержать существующий `claimId`, точный `sourceRef`, цитату, relation `SUPPORTS|CONTRADICTS|CONTEXT` и объяснение связи с критерием. Runtime MUST принимать только sourceRef и цитаты, разрешимые в переданном claim graph. `Соответствует` и `Не соответствует` MUST иметь хотя бы одно содержательное evidence; `Недостаточно данных` MAY не иметь evidence только при заполненных `missingData` и `followUpQuestion`.

#### Scenario: Модель подтверждает соответствие
- **WHEN** evaluator возвращает `Соответствует`
- **THEN** строка содержит хотя бы одну точную цитату и locator допустимого источника

#### Scenario: Модель придумала источник
- **WHEN** sourceRef или цитата отсутствуют в переданных claims
- **THEN** строка не принимается и получает точечный retry без повторения остальных критериев

#### Scenario: Сведений нет
- **WHEN** после gap-search отсутствует релевантный claim
- **THEN** строка равна `Недостаточно данных` и явно содержит недостающие данные и вопрос HR

### Requirement: MDA-011 ABC только из настроенного профиля
ABC assessment MUST использовать только vacancy ABC directions с непустыми определениями A, B и C и MUST сохранять результаты по `directionId`, а не по `criterionId` основной матрицы. Если пригодных направлений нет, ABC capability MUST NOT вызываться, а результат MUST явно обозначать ABC как не настроенный.

#### Scenario: Описания уровней ABC пусты
- **WHEN** у направлений вакансии отсутствуют определения A, B или C
- **THEN** система не создаёт технические ABC-строки из основной матрицы и показывает HR, что профиль не настроен
