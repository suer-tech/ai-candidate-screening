## Purpose

Определяет единый исполняемый контракт матрицы критериев версии вакансии, её ленивую компиляцию, независимую проверку и обязательное заполнение при оценке кандидата.

## ADDED Requirements

### Requirement: MDA-001 Ленивая матрица версии вакансии
При старте первого кандидата по зафиксированной `profileVersion` система MUST автоматически скомпилировать ровно одну матрицу критериев до извлечения оценочных claims. Материалы кандидата MUST NOT влиять на состав матрицы. Все последующие запуски по этой `profileVersion` MUST использовать опубликованный matrix artifact с тем же checksum.

#### Scenario: Первый кандидат запускает компиляцию
- **WHEN** кандидат начинает анализ по `profileVersion`, для которой matrix artifact отсутствует
- **THEN** система запускает shared-компиляцию из полной версии профиля
- **AND** не передаёт компилятору материалы кандидата

#### Scenario: Матрица уже существует
- **WHEN** другой кандидат начинает анализ по той же `profileVersion`
- **THEN** система переиспользует существующий matrix artifact без регенерации

### Requirement: MDA-002 Единственный конкурентный результат компиляции
Система MUST атомарно назначать одного владельца shared-компиляции, а конкурентные запуски MUST ожидать её результат. Публикация MUST быть идемпотентной; две различные матрицы для одной `profileVersion` MUST NOT становиться действующими.

#### Scenario: Два кандидата стартуют одновременно
- **WHEN** два запуска одновременно обнаруживают отсутствие матрицы
- **THEN** только один запуск получает compilation claim
- **AND** оба продолжают обработку с одним опубликованным checksum

#### Scenario: Shared-компиляция завершилась технической ошибкой
- **WHEN** compiler или единственный critic-editor не смог вернуть технически пригодную schema-valid матрицу после инфраструктурного retry
- **THEN** все ожидающие запуски получают одну типизированную причину ошибки
- **AND** последующий ручной повтор MAY создать новую попытку, пока matrix artifact не опубликован

### Requirement: MDA-003 Полная семантическая компиляция профиля
LLM-компилятор MUST получить полную неизменяемую версию профиля и создать дерево критериев с атомарными условиями, категориями, `ALL_OF`, `ANY_OF`, `AT_LEAST_N` либо `INFORMATIONAL`, LLM-определённой обязательностью, `hardRequired`, правилами проверки, ожидаемыми доказательствами, допустимыми состояниями, decision effect, точными `sourceRef` и interpretation notes. Детерминированный runtime MUST NOT определять семантический состав критериев, но MUST технически отклонять матрицу, где `hardRequired` не соответствует критерию из раздела стоп-факторов.

#### Scenario: Поле содержит несколько условий
- **WHEN** исходная формулировка содержит несколько связанных требований
- **THEN** компилятор сохраняет атомарные условия и исходную логическую связь
- **AND** каждая созданная строка ссылается на существующий фрагмент профиля

#### Scenario: Формулировка качественная
- **WHEN** профиль содержит качественное требование без числового порога
- **THEN** компилятор создаёт разумное качественное правило и interpretation note
- **AND** не придумывает срок, число, масштаб или новый кадровый порог

#### Scenario: Компилятор определяет обязательность
- **WHEN** существующий критерий по смыслу профиля является обязательным для выполнения роли
- **THEN** LLM-компилятор MAY установить `required: true` с explanation и точным sourceRef
- **AND** независимый критик проверяет, что классификация следует исходному профилю

#### Scenario: Критерий происходит из стоп-факторов
- **WHEN** sourceRef критерия относится к разделу стоп-факторов
- **THEN** компилятор устанавливает `hardRequired: true`
- **AND** критерий из другого раздела не может получить `hardRequired: true`

### Requirement: MDA-004 Единственная независимая критика с непосредственным исправлением
До публикации матрицы система MUST ровно один раз вызвать критика-редактора в чистом контексте, который не содержит reasoning компилятора. Критик MUST вернуть полный окончательный successor draft: без смысловых изменений со статусом `PASS` либо с самостоятельно внесёнными исправлениями и статусом `CORRECTED`. Отдельный repair skill и повторная критика MUST NOT выполняться. После единственного вызова система MUST продолжить с возвращённой матрицей; семантические замечания критика MUST NOT переводить обработку кандидата в terminal failure.

#### Scenario: Критик обнаружил выдуманный стоп-фактор
- **WHEN** исходный draft усиливает профиль или содержит выдуманный стоп-фактор
- **THEN** критик сам удаляет искажение в возвращаемом successor draft
- **AND** runtime не вызывает отдельный repair или повторного критика

#### Scenario: У критика остаётся неоднозначность
- **WHEN** исходный профиль допускает несколько разумных интерпретаций
- **THEN** критик выбирает best-effort интерпретацию, фиксирует audit note и возвращает полный successor
- **AND** обработка кандидата продолжается без нового цикла согласования моделей

### Requirement: MDA-005 Технические gates и неизменяемость
Перед публикацией runtime MUST проверить schema version, profile version, допустимые ID и enum, существование точных `sourceRef`, успешные protected traces, completeness и canonical checksum. После публикации matrix artifact MUST быть неизменяемым. Изменение compiler skill, модели или policy MUST NOT менять существующую матрицу; исправление её семантики требует новой версии профиля.

#### Scenario: Source reference отсутствует
- **WHEN** строка ссылается на несуществующий фрагмент профиля
- **THEN** технический gate отклоняет публикацию

#### Scenario: Compiler policy обновлена
- **WHEN** после публикации матрицы развёрнута новая compiler policy
- **THEN** запуски по прежней `profileVersion` продолжают использовать прежний checksum

### Requirement: MDA-006 Полное заполнение матрицы кандидата
Для каждого кандидата система MUST создать запись оценки для каждого `criterionId` с supporting и contradicting claim IDs, проверенными source IDs, состоянием, основанием, недостающими данными, follow-up вопросом и verification state. Пропуск строки MUST делать assessment невалидным.

#### Scenario: Доказательства отсутствуют
- **WHEN** проверенные материалы не содержат достаточного основания по критерию
- **THEN** строка сохраняется как `Недостаточно данных` с перечнем проверенных источников

#### Scenario: Строка пропущена
- **WHEN** LLM-ответ не содержит существующий `criterionId`
- **THEN** assessment gate отклоняет результат и запрашивает bounded repair только отсутствующей строки

### Requirement: MDA-007 Versioned bounded skills и tools
Смысловые стадии MUST исполняться versioned LLM skills с формальными input/output schemas и allowlist tools. Оркестратор MUST использовать предварительно проверенный durable DAG, grants, budgets и checkpoints; свободный ReAct-loop, произвольные tools и самостоятельное изменение формулы рекомендации MUST быть запрещены.

#### Scenario: Skill запрашивает неразрешённый tool
- **WHEN** модель пытается вызвать операцию вне allowlist текущей задачи
- **THEN** runtime отклоняет вызов и сохраняет безопасный audit event

### Requirement: MDA-008 Критический риск вне матрицы
Непредусмотренный отрицательный сигнал MUST оставаться информационным по умолчанию. Он MAY стать `criticalUnmappedRisk` только после отдельной LLM-оценки существенности и независимой LLM-верификации в чистом контексте. Обе стадии MUST ссылаться на допустимые candidate-scoped evidence locators, объяснять связь с выполнением роли и исключать чувствительные нерелевантные признаки. Неподтверждённый либо несущественный сигнал MUST NOT становиться отказным основанием.

#### Scenario: Обнаружен существенный отрицательный факт вне матрицы
- **WHEN** open pass находит доказанный факт, отсутствующий среди критериев профиля, который может критически препятствовать выполнению роли
- **THEN** risk-assessment skill классифицирует его с evidence locators и обоснованием существенности
- **AND** независимый verification skill подтверждает либо отклоняет `criticalUnmappedRisk`

#### Scenario: Критичность не подтверждена
- **WHEN** независимая проверка не подтверждает доказательство, существенность или допустимость сигнала
- **THEN** сигнал остаётся информационным и не меняет рекомендацию
