## MODIFIED Requirements

### Requirement: VAC-011 [CONFIRMED] Структура обязательного опыта
Для каждого требования обязательного опыта система SHALL хранить формулировку, ожидаемый уровень или длительность при применимости, допустимые эквиваленты и правило подтверждения либо примеры достаточных фактов. Качественная формулировка MAY быть утверждена HR без числового порога. Отдельный пользовательский раздел или переключатель `required`/`hardRequired` MUST NOT требоваться: матричный LLM-компилятор MUST определить `required` из полной семантики зафиксированного профиля, а независимый критик MUST проверить классификацию без усиления исходного смысла.

#### Scenario: HR задаёт обязательный опыт
- **WHEN** HR добавляет требование обязательного опыта
- **THEN** система позволяет заполнить содержательные поля требования без отдельного переключателя `hardRequired`
- **AND** сохранённая версия содержит достаточный исходный текст для best-effort компиляции правила

#### Scenario: Качественное обязательное требование
- **WHEN** HR утверждает заполненное качественное правило без числового порога
- **THEN** система сохраняет его в зафиксированной версии профиля
- **AND** LLM-компилятор определяет requiredness по смыслу профиля и сохраняет interpretation note
- **AND** не превращает его в `hardRequired`, если sourceRef не относится к разделу стоп-факторов

### Requirement: VAC-012 [CONFIRMED] Структура стоп-фактора
Для каждого стоп-фактора система SHALL хранить формулировку, условия срабатывания и ожидаемый тип доказательства. Каждый критерий матрицы, происходящий из раздела стоп-факторов, MUST иметь `hardRequired: true`; критерий из любого другого раздела MUST NOT иметь `hardRequired: true`. ABC-оценка сама по себе MUST NOT считаться стоп-фактором.

#### Scenario: HR добавляет стоп-фактор
- **WHEN** HR добавляет стоп-фактор в профиль
- **THEN** система требует описать условие срабатывания и тип подтверждающего доказательства
- **AND** LLM-компилятор создаёт связанный `hardRequired` criterion с точным sourceRef

#### Scenario: ABC-признак не оформлен стоп-фактором
- **WHEN** профиль содержит критичный ABC-признак вне раздела стоп-факторов
- **THEN** компилятор MUST NOT присваивать ему `hardRequired`
- **AND** одна только оценка A, B или C не активирует стоп-фактор автоматически

#### Scenario: ABC-признак критичен для вакансии
- **WHEN** HR хочет, чтобы конкретный ABC-признак всегда приводил к результату `Не рекомендовать`
- **THEN** HR описывает его условие в разделе стоп-факторов
- **AND** компилятор создаёт для этого sourceRef критерий с `hardRequired: true`

## ADDED Requirements

### Requirement: VAC-040 Утверждение профиля не является утверждением матрицы
HR MUST просматривать и явно утверждать профиль и ABC-определения до активации, но MUST NOT быть обязан просматривать или утверждать автоматически скомпилированную матрицу. Матрица MUST создаваться лениво при первом candidate run.

#### Scenario: Профиль активирован
- **WHEN** HR утвердил заполненную версию профиля
- **THEN** версия доступна для запуска кандидатов без предварительной компиляции матрицы
