## Why

Локальный Windows-контур и production VPS сейчас полагаются на технический principal либо nginx Basic Auth, из-за чего приложение не имеет собственного управляемого входа, сессий и жизненного цикла пользователей. Для рабочего использования нужен единый серверный вход по корпоративной почте и паролю, который закрывает UI и API от посторонних и одинаково работает локально и на VPS.

## What Changes

- Добавляется полноценная серверная аутентификация по корпоративной почте и паролю для локального и VPS-контуров.
- Добавляются закрыто создаваемые HR-учётные записи, безопасные password hashes, обязательная смена временного пароля, блокировка/разблокировка и отзыв сессий; публичной регистрации нет.
- Добавляются защищённые HttpOnly-сессии, «Запомнить меня», истечение, выход, принудительный отзыв и CSRF-защита изменяющих запросов.
- Все рабочие страницы и product API переходят на fail-closed проверку серверной сессии; неавторизованный пользователь видит только брендированный экран входа без кандидатских данных.
- Добавляются ограничение попыток входа, временная блокировка и журнал security-событий без паролей, session tokens и лишних персональных данных.
- Добавляются операторские команды создания HR, выдачи временного пароля, отключения учётной записи и отзыва её сессий.
- **BREAKING**: на VPS nginx Basic Auth и постоянный заголовок `oai-authenticated-user-id` перестают быть источником пользовательской идентичности; nginx удаляет входящие identity headers, а principal создаётся только из валидной сессии приложения.
- Локальный контур получает тот же PostgreSQL-механизм; разрешённые тестовые обходы остаются только в явно локальном E2E-режиме и никогда не включаются в production.
- `chatgpt.site`, Sites/D1/R2 и опубликованный дизайн-сайт не входят в изменение и не переиздаются.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `data-and-security`: заменить техническую/Basic Auth идентификацию локального и VPS-контуров полноценными password credentials, серверными сессиями, защитой от перебора и управляемым жизненным циклом HR-учётных записей.

## Impact

- PostgreSQL schema и forward-only migration для пользователей, сессий, попыток входа и security-аудита.
- Серверные auth services/routes, единая async-проверка principal для UI и API, CSRF boundary.
- Экран входа, смена временного пароля, завершение сессии и выход в профиле.
- Локальные runtime-команды, production preflight, nginx-конфигурация и эксплуатационная документация VPS.
- Приёмочные, интеграционные и security-тесты; обязательный production E2E-контур перед релизом.
