## MODIFIED Requirements

### Requirement: VAC-014 [CONFIRMED] Набор обязательных полей для активации
Первичное создание active vacancy MUST требовать только непустое уникальное название и успешный Google Drive binding. Параметры оценки MAY быть пустыми в version 1 и MUST NOT запускать RouterAI при создании. Для участия вакансии в автоматическом анализе кандидата последующая сохранённая версия профиля MUST содержать полный набор обязательных полей; он MAY быть получен отдельной генерацией либо заполнен HR вручную.

#### Scenario: Все обязательные поля заполнены
- **WHEN** HR вводит уникальное название и нажимает `Сохранить`
- **THEN** система создаёт active vacancy версии 1 без LLM-вызова
- **AND** открывает пустые параметры и действие `Сгенерировать описание`

#### Scenario: Обязательный раздел не заполнен
- **WHEN** HR пытается сохранить и активировать профиль без одного из обязательных полей или разделов
- **THEN** система блокирует действие и указывает каждое конкретное незаполненное поле
- **AND** введённые значения остаются в текущем unsaved editor для исправления

#### Scenario: HR удалил стандартное ABC-направление
- **WHEN** оставшийся ABC-набор содержит минимум одно направление и каждое направление полностью заполнено и утверждено
- **THEN** отсутствие удалённого стандартного направления не блокирует финальное подтверждение

#### Scenario: Профиль изменён после preview
- **WHEN** HR изменяет любое поле уже просмотренного snapshot
- **THEN** прежнее подтверждение сбрасывается
- **AND** система требует повторно просмотреть и подтвердить изменённый профиль

### Requirement: VAC-019 [CONFIRMED] Сохранение полного и активация утверждённого ABC-профиля
Любая версия профиля после минимальной version 1 SHALL содержать как минимум одно ABC-направление, а у каждого направления SHALL быть заполнены название и конкретные наблюдаемые определения A, B и C. Временно неполное состояние MAY существовать в editor созданной vacancy и MUST NOT сохраняться как новая полная версия. Действие в параметрах MUST называться `Сохранить`.

#### Scenario: HR редактирует неполное направление
- **WHEN** HR оставляет в сгенерированном профиле направление с незаполненным определением
- **THEN** система сохраняет введённые значения только в текущем editor для дальнейшего исправления
- **AND** новая версия профиля не создаётся, а vacancy сохраняется

#### Scenario: Удалены все направления
- **WHEN** HR удаляет все направления и запрашивает финальное сохранение
- **THEN** система отклоняет действие и сообщает, что требуется хотя бы одно направление
- **AND** текущий editor остаётся доступным для исправления, а версия не создаётся

#### Scenario: Название направления пустое
- **WHEN** HR сохраняет профиль с пустым или состоящим только из пробелов названием направления
- **THEN** система отклоняет действие и указывает соответствующее направление и поле названия
- **AND** версия не создаётся

#### Scenario: Определение A, B или C пустое
- **WHEN** HR сохраняет профиль с пустым или состоящим только из пробелов определением A, B или C
- **THEN** система отклоняет действие и указывает соответствующее направление и оценку
- **AND** версия не создаётся

#### Scenario: Ошибка сохраняет значения черновика
- **WHEN** финальное действие отклонено из-за невалидного ABC-профиля
- **THEN** все идентификаторы, значения, происхождение и порядок направлений остаются в текущей browser session
- **AND** новая версия не создаётся, а существующая vacancy сохраняется

#### Scenario: Полный ABC-профиль проходит проверку
- **WHEN** профиль сгенерирован или заполнен вручную, содержит хотя бы одно полное направление и все обязательные поля заполнены
- **THEN** `Сохранить` создаёт ровно одну следующую immutable version существующей vacancy
- **AND** повторная доставка того же operation ID не создаёт дубль версии

#### Scenario: Определения ещё не утверждены HR
- **WHEN** HR пытается выполнить финальное действие без подтверждения текущего snapshot
- **THEN** система блокирует сохранение и активацию
- **AND** предлагает проверить и утвердить определения A/B/C

### Requirement: VAC-034 [CONFIRMED] Сохранение создаёт вакансию и первую версию
Действие `Сохранить` на create screen SHALL создавать устойчивый vacancy ID, active vacancy, минимальную неизменяемую version 1 и idempotent Google Drive folder binding без LLM-вызова. Действие `Сохранить` в параметрах существующей вакансии SHALL сохранять новую полную версию профиля. Safe retry MUST завершать ту же operation без дублей.

#### Scenario: HR сохраняет отредактированный черновик
- **WHEN** profile validation, version persistence и Drive binding успешны
- **THEN** HR видит одну active vacancy версии 1
- **AND** после повторного открытия отображаются подтверждённые правки HR, а не исходный ответ модели
- **AND** vacancy доступна штатному intake и analysis

#### Scenario: Drive binding временно не завершён
- **WHEN** профиль валиден и подтверждён, но обязательная Drive operation завершилась ошибкой
- **THEN** интерфейс показывает save error и допускает safe retry той же operation
- **AND** vacancy не видна как active и не принимает кандидатов

### Requirement: VAC-037 [CONFIRMED] Ошибка отдельной генерации не повреждает созданную вакансию
Generation operation MUST запускаться только по кнопке `Сгенерировать описание` внутри существующей вакансии. Для timeout, network error, HTTP 429/5xx и невалидного structured response система MUST выполнить bounded retry с тем же operation ID. Ошибка MUST NOT удалять vacancy, менять текущую сохранённую версию или очищать editor. После terminal error UI SHALL показать безопасную причину и разрешить повторить генерацию.

#### Scenario: Временная ошибка устраняется повтором
- **WHEN** первоначальный вызов и часть повторов завершаются повторяемой ошибкой, а последующий вызов возвращает валидный профиль
- **THEN** система автоматически продолжает generation operation без действия HR
- **AND** показывает editor один раз с валидным результатом

#### Scenario: Три автоматических повтора исчерпаны
- **WHEN** первоначальный вызов и три автоматических повтора не сформировали валидный профиль
- **THEN** система сообщает, что описание вакансии не удалось сформировать после четырёх попыток
- **AND** показывает безопасную причину и действие `Повторить генерацию`
- **AND** созданная vacancy, Drive binding и текущая версия остаются неизменными

#### Scenario: LLM возвращает ошибку
- **WHEN** generation operation завершается terminal error после разрешённых автоматических повторов либо немедленной неповторяемой ошибкой
- **THEN** новая версия описания не создаётся
- **AND** HR получает понятное безопасное сообщение, а прежние значения остаются в editor

#### Scenario: HR повторно нажимает кнопку во время генерации
- **WHEN** generation operation уже выполняется
- **THEN** повторное действие не запускает параллельную operation
- **AND** UI показывает состояние и номер текущей попытки

#### Scenario: Провайдер вернул неповторяемую ошибку
- **WHEN** сервер определяет ошибку авторизации или конфигурации, которую повтор не исправит
- **THEN** автоматические повторы не расходуются безрезультатно
- **AND** HR получает понятное сообщение о временной недоступности формирования без секретов и raw provider response

## ADDED Requirements

### Requirement: VAC-042 [CONFIRMED] Канонические ABC-направления первичной генерации
Успешная первичная LLM-генерация MUST возвращать ровно пять ABC-направлений в следующем порядке: `Продуктивность`, `Инициатива`, `Самообучаемость`, `Корпоративные ценности`, `Автономность`. Для каждого направления MUST быть заполнены конкретные наблюдаемые определения A, B и C. Иное название, порядок, количество, пропуск или повтор SHALL делать structured response невалидным и запускать действующую bounded retry policy. После успешной генерации HR MAY редактировать либо удалять направления по общим правилам unsaved editor; это не меняет обязательный исходный generated snapshot.

#### Scenario: Модель вернула канонический ABC-набор
- **WHEN** structured response содержит пять канонических направлений в установленном порядке и полные определения A/B/C
- **THEN** сервер принимает ABC-часть generated snapshot
- **AND** UI показывает направления в том же порядке

#### Scenario: Модель вернула случайные направления
- **WHEN** название, порядок или количество ABC-направлений отличается от канонического набора
- **THEN** сервер отклоняет structured response как невалидный
- **AND** не создаёт vacancy, version или persistent draft до успешного bounded retry

### Requirement: VAC-043 [CONFIRMED] Содержательные и читаемые разделы профиля
Первичная генерация MUST содержать четыре раздела и сохранять каждый как читаемый многострочный набор смысловых пунктов без склейки через `; ` в одну строку. `Образ результата` MUST описывать цель должности, ожидаемые результаты, измеримость и масштаб; `Компетенции` MUST включать 2–3 критических профессиональных навыка и наблюдаемые признаки подтверждения; `Стоп-факторы` MUST содержать отдельные проверяемые условия, условие срабатывания и требуемый тип доказательства; `Допуск к КЕ` MUST содержать обязательные пункты проверки, признак готовности, обязательность и источник результата. UI MUST сохранять переносы строк в editor и давать HR редактировать каждый раздел без горизонтальной непрерывной строки.

#### Scenario: Модель вернула массивы и вложенные объекты
- **WHEN** structured response содержит смысловые пункты разделов в массивах либо объектах
- **THEN** сервер детерминированно преобразует каждый пункт в отдельную строку с короткой меткой
- **AND** не теряет содержимое, порядок и вложенные наблюдаемые признаки

#### Scenario: HR открывает параметры созданной вакансии
- **WHEN** HR выбирает любой из четырёх профильных разделов
- **THEN** editor отображает смысловые пункты построчно с переносом текста
- **AND** длинное содержимое не становится одной непрерывной горизонтальной строкой

### Requirement: VAC-044 [CONFIRMED] Представление generated profile форматируется детерминированно
Система MUST строить пользовательский текст четырёх generated-разделов из structured response на сервере, а не полагаться на пробелы и оформление свободного ответа модели. Известные технические ключи MUST отображаться утверждёнными русскими заголовками. Между соседними смысловыми блоками верхнего уровня MUST быть ровно одна пустая строка; элементы массивов и вложенные признаки MUST иметь единообразные маркеры и отступы без склеенных слов, случайных двойных пробелов и необработанного camelCase.

#### Scenario: RouterAI возвращает вложенный объект с техническими ключами
- **WHEN** generated `Образ результата` содержит `positionGoal`, `measurableResults`, `metrics` и `personalContribution`
- **THEN** persisted editor text содержит русские заголовки `Цель должности`, `Измеримые результаты`, `Метрики` и `Личный вклад`
- **AND** верхнеуровневые блоки разделены пустой строкой, а значения массивов оформлены маркерами

#### Scenario: Модель меняет пробелы в structured response
- **WHEN** значения содержат начальные, конечные или повторяющиеся пробелы
- **THEN** formatter нормализует их без изменения смыслового порядка
- **AND** результат не зависит от исходного текстового оформления модели

### Requirement: VAC-040 [CONFIRMED] Название вакансии обязательно и уникально
Название SHALL быть непустым и уникальным после trim, схлопывания whitespace и регистронезависимого сравнения. Проверка MUST выполняться на server boundary atomic create operation. Создание MUST NOT обращаться к LLM.

#### Scenario: Нормализованный duplicate найден
- **WHEN** существуют `Бизнес ассистент` и HR вводит `  бизнес   ассистент `
- **THEN** система отклоняет название как duplicate
- **AND** не создаёт vacancy или Drive folder

#### Scenario: Название принято
- **WHEN** HR вводит непустое уникальное название и нажимает `Сохранить`
- **THEN** сервер создаёт vacancy и Drive binding идемпотентно
- **AND** не запускает LLM-генерацию

### Requirement: VAC-041 [CONFIRMED] Unsaved editor не образует persistent draft lifecycle
Create screen MUST содержать только название и MUST NOT образовывать persistent draft. Editor параметров принадлежит уже созданной vacancy и доступен до генерации. `Сгенерировать описание` заполняет unsaved editor валидным snapshot; `Сбросить изменения` восстанавливает последнюю сохранённую версию, а действие в каждом разделе называется `Сохранить`.

#### Scenario: HR покидает изменённую форму
- **WHEN** HR выбирает back или navigation после изменения сгенерированного профиля
- **THEN** система запрашивает discard confirmation
- **AND** подтверждение восстанавливает последнюю сохранённую версию без создания новой version

#### Scenario: HR сбрасывает изменения
- **WHEN** HR подтверждает `Сбросить изменения`
- **THEN** editor возвращается к последней сохранённой версии профиля
- **AND** новый LLM call или новая version не создаются

#### Scenario: Генерация не завершилась успешно
- **WHEN** generation operation завершилась terminal error
- **THEN** система оставляет текущий editor и прежние значения без изменений
- **AND** HR может заполнить параметры вручную или повторить генерацию

### Requirement: VAC-045 [CONFIRMED] Генерация описания отделена от создания vacancy
В карточке созданной вакансии MUST быть кнопка `Сгенерировать описание`. Она MUST запускать RouterAI только по явному клику, показывать progress/retry state и после валидного результата заполнять `Образ результата`, ABC, `Компетенции`, `Стоп-факторы` и `Допуск к КЕ` без автоматического сохранения. HR MUST сохранить результат действием `Сохранить`.

#### Scenario: HR создаёт вакансию
- **WHEN** HR сохраняет новое уникальное название
- **THEN** vacancy появляется без ожидания RouterAI
- **AND** профиль пуст, а кнопка `Сгенерировать описание` доступна

#### Scenario: HR генерирует описание
- **WHEN** HR нажимает `Сгенерировать описание` внутри vacancy и RouterAI возвращает валидный профиль
- **THEN** все разделы заполняются в editor
- **AND** новая версия появляется только после действия `Сохранить`

#### Scenario: Подпись сохранения единообразна
- **WHEN** HR открывает любой раздел параметров оценки
- **THEN** основное действие называется `Сохранить`
- **AND** текст `Сохранить новую версию` отсутствует
