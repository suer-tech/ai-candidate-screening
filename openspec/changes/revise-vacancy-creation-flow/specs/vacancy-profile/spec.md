## MODIFIED Requirements

### Requirement: VAC-014 [CONFIRMED] Набор обязательных полей для активации
Действие `Сохранить вакансию` MUST принимать только профиль с непустыми `Название вакансии` и `Образ результата`; минимум одним ABC-направлением с непустыми конкретными A/B/C; минимум одним полным пунктом `Доступ к КЕ`; минимум одним полным стоп-фактором; минимум одной компетенцией с правилами и наблюдаемыми признаками; и без логических противоречий. Успешное сохранение MUST сразу создавать active неизменяемую версию без отдельного preview, draft либо activation state.

#### Scenario: Все обязательные поля заполнены
- **WHEN** HR сохраняет полный непротиворечивый профиль
- **THEN** система создаёт active vacancy и первую неизменяемую версию
- **AND** отдельное подтверждение preview или activation не требуется

#### Scenario: Обязательный раздел не заполнен
- **WHEN** HR сохраняет профиль без обязательного поля
- **THEN** система блокирует save и указывает каждое невалидное поле
- **AND** vacancy не становится active

#### Scenario: HR удалил стандартное ABC-направление
- **WHEN** оставшийся ABC-набор содержит минимум одно полностью заполненное направление
- **THEN** отсутствие удалённого стандартного направления не блокирует `Сохранить вакансию`
- **AND** сохранение по-прежнему требует валидности всех остальных обязательных разделов

### Requirement: VAC-015 [CONFIRMED] Стандартный ABC-шаблон новой вакансии
После принятия уникального названия система SHALL создать в несохранённом editor независимую копию пяти стандартных направлений: продуктивность, инициатива, самообучаемость, соответствие корпоративным ценностям и автономность. Каждое направление SHALL иметь базовые непустые A/B/C без LLM-адаптации; изменение формы MUST NOT изменять template или другие вакансии.

#### Scenario: Создан черновик новой вакансии
- **WHEN** HR завершает первый шаг с валидным уникальным названием
- **THEN** editor содержит независимые копии пяти стандартных ABC-направлений с A/B/C
- **AND** никакой LLM call не выполняется

### Requirement: VAC-019 [CONFIRMED] Сохранение полного и активация утверждённого ABC-профиля
Сохранённая версия SHALL содержать минимум одно полностью заполненное ABC-направление с уникальным нормализованным названием. Неполное состояние MAY существовать только в текущем browser editor и MUST NOT сохраняться как draft или новая версия. Единственное действие `Сохранить вакансию` MUST валидировать профиль и при успехе создать ровно одну active версию.

#### Scenario: HR редактирует неполное направление
- **WHEN** HR нажимает `Сохранить вакансию` с пустым названием направления либо A/B/C
- **THEN** система сохраняет введённые значения только в текущей форме для исправления
- **AND** vacancy и версия не создаются

#### Scenario: Удалены все направления
- **WHEN** HR удаляет все направления и нажимает `Сохранить вакансию`
- **THEN** система отклоняет сохранение и сообщает, что требуется хотя бы одно направление
- **AND** значения остаются в текущей форме для исправления, а версия не создаётся

#### Scenario: Название направления пустое
- **WHEN** HR сохраняет форму с пустым или пробельным названием направления
- **THEN** система отклоняет сохранение и указывает соответствующее поле
- **AND** версия не создаётся

#### Scenario: Определение A, B или C пустое
- **WHEN** HR сохраняет форму с пустым или пробельным определением A, B или C
- **THEN** система отклоняет сохранение и указывает соответствующее направление и оценку
- **AND** версия не создаётся

#### Scenario: Ошибка сохраняет значения черновика
- **WHEN** save отклонён из-за невалидного ABC-профиля
- **THEN** текущая browser form сохраняет введённые значения и порядок для исправления в этой сессии
- **AND** persistent draft или новая версия не создаются

#### Scenario: Полный ABC-профиль проходит проверку
- **WHEN** HR один раз сохраняет валидный полный профиль
- **THEN** создаётся ровно одна active vacancy и версия 1
- **AND** повторная доставка того же operation id не создаёт дубль

#### Scenario: Определения ещё не утверждены HR
- **WHEN** HR ещё не выполнил итоговое действие `Сохранить вакансию`
- **THEN** значения остаются только в unsaved editor и не участвуют в intake или analysis
- **AND** отдельное утверждение A/B/C либо activation action не создаётся

### Requirement: VAC-020 [CONFIRMED] Логически противоречивый профиль нельзя сохранить
Система MUST NOT сохранять и автоматически активировать профиль с логически противоречащими параметрами, включая случай, когда один признак одновременно разрешён и объявлен стоп-фактором.

#### Scenario: Обнаружено противоречие правил
- **WHEN** HR сохраняет профиль с взаимоисключающими параметрами
- **THEN** система блокирует save и automatic activation
- **AND** показывает конфликтующие правила для исправления

### Requirement: VAC-030 [CONFIRMED] Первый шаг создания содержит только название
По действию `Новая вакансия` система SHALL открыть первый шаг только с обязательным полем `Название вакансии` и действием продолжения. После server validation названия система SHALL сразу открыть полный ручной editor; кнопка генерации и LLM-формирование начального профиля MUST отсутствовать.

#### Scenario: HR начинает создание вакансии
- **WHEN** HR выбирает `Новая вакансия`
- **THEN** система показывает только поле названия и действие продолжения
- **AND** не показывает `Сформировать вакансию` или поля профиля до принятия названия

### Requirement: VAC-034 [CONFIRMED] Сохранение создаёт вакансию и первую версию
Успешный save SHALL создавать устойчивый vacancy ID, active vacancy, первую неизменяемую версию полного профиля и idempotent Drive folder binding как один externally atomic outcome. Пока любой обязательный шаг не завершён, save MUST NOT показываться успешным, а vacancy MUST NOT участвовать в intake или analysis. Safe retry MUST завершать ту же operation без дублей.

#### Scenario: HR сохраняет отредактированный черновик
- **WHEN** profile validation, version persistence и Drive binding успешны
- **THEN** HR видит одну active vacancy версии 1
- **AND** vacancy сразу доступна штатному intake и analysis

#### Scenario: Drive binding временно не завершён
- **WHEN** профиль валиден, но обязательная Drive operation завершилась ошибкой
- **THEN** интерфейс показывает save error и допускает safe retry
- **AND** vacancy не видна как active и не принимает кандидатов

## ADDED Requirements

### Requirement: VAC-040 [CONFIRMED] Название вакансии обязательно и уникально
Название SHALL быть непустым и уникальным после trim, схлопывания последовательностей whitespace и регистронезависимого сравнения. Проверка MUST выполняться на server boundary до открытия editor и повторно в atomic save operation.

#### Scenario: Нормализованный duplicate найден
- **WHEN** существуют `Бизнес ассистент` и HR вводит `  бизнес   ассистент `
- **THEN** система отклоняет название как duplicate
- **AND** не открывает editor для новой vacancy

### Requirement: VAC-041 [CONFIRMED] Unsaved editor не образует draft lifecycle
Система MUST NOT сохранять несохранённый create-vacancy editor как draft. Cancel, back или navigation с изменениями SHALL требовать discard confirmation; подтверждение и page reload SHALL очищать unsaved state. Действие `Сбросить настройки` SHALL после подтверждения восстановить initial non-LLM template.

#### Scenario: HR покидает изменённую форму
- **WHEN** HR выбирает back или navigation после изменения unsaved profile
- **THEN** система запрашивает discard confirmation
- **AND** подтверждение очищает unsaved state без создания vacancy

#### Scenario: HR сбрасывает настройки
- **WHEN** HR подтверждает `Сбросить настройки`
- **THEN** editor возвращается к исходному title и standard template state
- **AND** persisted vacancy или version не создаётся

## REMOVED Requirements

### Requirement: VAC-021 [CONFIRMED] Предварительный просмотр перед активацией
**Reason**: Новый create flow не имеет отдельного preview/activation lifecycle.
**Migration**: Полная server validation выполняется внутри `Сохранить вакансию`; save автоматически активирует версию.

### Requirement: VAC-031 [CONFIRMED] LLM вызывается только через серверный контур
**Reason**: LLM generation удалена из create-vacancy flow.
**Migration**: HR заполняет profile вручную после принятия title.

### Requirement: VAC-032 [CONFIRMED] Структура сгенерированного черновика
**Reason**: Generated draft больше не существует.
**Migration**: Полный profile contract проверяется server validation при save.

### Requirement: VAC-033 [CONFIRMED] Сгенерированные критерии доступны для редактирования
**Reason**: Initial profile не генерируется моделью.
**Migration**: Manual editor открывается со standard non-LLM template.

### Requirement: VAC-037 [CONFIRMED] Ошибки генерации не создают частичную вакансию
**Reason**: Generation request удалён.
**Migration**: Ошибки title validation, profile validation и Drive binding покрываются новым atomic save contract.

### Requirement: VAC-038 [CONFIRMED] Генерация трассируется без раскрытия секретов
**Reason**: Vacancy generation call удалён.
**Migration**: Tracing других LLM capabilities регулируется отдельным change.

### Requirement: VAC-039 [TBD] Параметры и критерии качества LLM
**Reason**: LLM generation не сохраняется как альтернативный create flow.
**Migration**: Requirement удаляется без замены в vacancy-profile capability.
