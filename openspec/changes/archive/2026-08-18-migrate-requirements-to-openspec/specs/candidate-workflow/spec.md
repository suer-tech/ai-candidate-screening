## Purpose

Определяет обнаружение и версионирование материалов кандидата, проверку стабильности загрузки, машину состояний, идемпотентность и наблюдаемый сквозной процесс обработки.

## ADDED Requirements

### Requirement: WF-001 [CONFIRMED] Источник входных материалов
Источником входных материалов SHALL быть выделенная отслеживаемая область Google Drive.

#### Scenario: Файл находится вне отслеживаемой области
- **WHEN** материал создан вне согласованной области
- **THEN** система не принимает его как вход кандидата этого workflow

### Requirement: WF-002 [CONFIRMED] Иерархия папок
Отслеживаемая структура MUST использовать иерархию `Найм/<Вакансия>/<Кандидат>/`, где папка кандидата содержит резюме, интервью и дополнительные материалы, а пользовательские результаты находятся только в `Результаты/vNNNN/`. Каталог `Результаты/` и всё его содержимое MUST исключаться из обнаружения, проверки стабильности и версионирования входных материалов. Имена сегментов MUST использоваться только для отображения и MUST NOT определять техническую идентичность вакансии или кандидата.

#### Scenario: Материалы размещены в согласованной структуре
- **WHEN** папка кандидата создана внутри папки вакансии в корне `Найм`
- **THEN** система обнаруживает папку и проверяет содержащиеся в ней материалы

#### Scenario: В папке опубликованы результаты
- **WHEN** сканирование обнаруживает файлы внутри `Результаты/vNNNN/`
- **THEN** они не входят во входной комплект и не запускают новую обработку

### Requirement: WF-003 [CONFIRMED] Техническая идентичность кандидата
При первом обнаружении папки кандидата система MUST создать внутренний UUID и сохранить связь с её Google Drive Folder ID и внутренним ID вакансии. Имя и путь папки MUST использоваться только для отображения. Переименование или перемещение папки MUST NOT создавать дубликат. Папка-копия с новым Google Drive Folder ID MUST считаться новым кандидатом; объединение кандидатов не входит в этот workflow без отдельного change. Если Folder ID присутствует в tombstone удалённого кандидата, система MUST NOT создавать его повторно и MUST NOT восстанавливать персональные данные автоматически.

#### Scenario: Папка кандидата переименована
- **WHEN** отображаемое имя существующей папки меняется
- **THEN** система связывает её с прежним кандидатом по устойчивой идентичности
- **AND** не создаёт второй объект обработки

#### Scenario: Папка кандидата перемещена внутри отслеживаемой структуры
- **WHEN** папка с прежним Google Drive Folder ID перемещается к другому пути
- **THEN** внутренний UUID кандидата сохраняется
- **AND** внутренняя связь с вакансией не меняется автоматически из-за нового пути

#### Scenario: Создана копия папки
- **WHEN** в отслеживаемой структуре появляется папка с новым Google Drive Folder ID
- **THEN** система создаёт нового кандидата с новым внутренним UUID

#### Scenario: Обнаружена папка удалённого кандидата
- **WHEN** сканер видит Google Drive Folder ID, сохранённый в tombstone
- **THEN** новый кандидат не создаётся и обработка не запускается

### Requirement: WF-010 [CONFIRMED] Минимальный комплект
Минимальный комплект для автоматического запуска SHALL состоять из резюме и одной аудио- или видеозаписи интервью вне каталога `Результаты/`.

#### Scenario: Оба обязательных материала присутствуют
- **WHEN** стабильный комплект содержит резюме и поддерживаемую запись интервью
- **THEN** система признаёт минимальный комплект полным

### Requirement: WF-011 [CONFIRMED] Недостаточно материалов
При отсутствии резюме или одной аудио- либо видеозаписи интервью система SHALL присваивать состояние `MATERIALS_INCOMPLETE`, отображаемое пользователю как `Недостаточно материалов`, и перечислять недостающие материалы. В этом состоянии анализ MUST NOT запускаться. `MATERIALS_INCOMPLETE` MUST применяться к отсутствующему обязательному материалу, а не к присутствующему файлу, который оказался повреждённым или неподдерживаемым уже при обработке.

#### Scenario: Нет записи интервью
- **WHEN** стабильная папка содержит резюме, но не содержит поддерживаемую запись
- **THEN** кандидат получает состояние недостатка материалов
- **AND** сообщение явно указывает отсутствие записи

### Requirement: WF-012 [CONFIRMED] Частичная загрузка не обрабатывается
Система MUST NOT начинать обработку частично загруженного или изменяющегося файла.

#### Scenario: Размер файла продолжает меняться
- **WHEN** очередной снимок показывает изменение размера
- **THEN** система продолжает ожидание стабильности
- **AND** не запускает дорогостоящие этапы

### Requirement: WF-013 [CONFIRMED] Периодичность обнаружения и проверки
Система SHALL проверять отслеживаемую область на новые папки каждые 15 секунд, а после обнаружения папки SHALL проверять стабильность её файлов один раз в минуту.

#### Scenario: Обнаружена новая папка
- **WHEN** 15-секундный цикл обнаруживает новую папку кандидата
- **THEN** система переводит её в ожидание стабильности
- **AND** запускает минутный цикл снимков

### Requirement: WF-014 [CONFIRMED] Новая версия входного комплекта
Первый полный стабильный комплект SHALL запускать анализ автоматически. Последующее добавление, удаление или изменение материала MUST создавать новую версию входного комплекта и MUST NOT автоматически запускать повторный анализ. Активный запуск MUST использовать неизменяемый снимок выбранной версии и MUST NOT подмешивать в него последующие изменения. После стабилизации новой версии система MUST проверить её полноту, уведомить HR в интерфейсе о доступном обновлении и ожидать явного ручного запуска. Прежний результат MUST оставаться доступным без изменений.

#### Scenario: После READY изменён файл
- **WHEN** система обнаруживает новую версию использованного материала
- **THEN** прежний анализ сохраняет прежние входные версии
- **AND** создаётся новая версия комплекта без автоматической повторной обработки
- **AND** после проверки стабильности и полноты HR видит предложение запустить повторный анализ

#### Scenario: Файл изменён во время активного запуска
- **WHEN** после начала анализа система обнаруживает добавление, удаление или изменение входного файла
- **THEN** активный запуск продолжается на ранее зафиксированном неизменяемом снимке
- **AND** изменённые материалы образуют отдельную версию, ожидающую стабилизации и решения HR

### Requirement: WF-015 [CONFIRMED] Три стабильных минутных интервала
Комплект SHALL считаться стабильно загруженным после трёх последовательных полных минутных интервалов, в которых одновременно не изменились количество файлов и размер ни одного файла, после первого зафиксированного снимка.

#### Scenario: Три сравнения подряд неизменны
- **WHEN** три последовательных минутных сравнения подтверждают одинаковое количество и размеры файлов
- **THEN** система признаёт загрузку стабильной

### Requirement: WF-016 [CONFIRMED] Изменение сбрасывает стабильность
Изменение количества файлов или размера любого файла SHALL обнулять счётчик стабильности и начинать новый трёхминутный отсчёт от обновлённого снимка.

#### Scenario: На втором интервале добавлен файл
- **WHEN** до завершения трёх стабильных интервалов меняется состав папки
- **THEN** накопленный счётчик сбрасывается
- **AND** новый отсчёт начинается от текущего снимка

### Requirement: WF-017 [CONFIRMED] Повторная проверка минимального комплекта
После подтверждения стабильности система SHALL повторно проверить минимальный комплект, перевести полный комплект в `MATERIALS_READY` и запустить обработку либо перевести неполный комплект в `MATERIALS_INCOMPLETE`.

#### Scenario: Стабильная папка стала полной
- **WHEN** завершается третья стабильная проверка и обязательные материалы присутствуют
- **THEN** система фиксирует `MATERIALS_READY`
- **AND** запускает обработку

### Requirement: WF-018 [CONFIRMED] Момент начала измерения времени
Моментом готовности комплекта и началом измерения фактического времени относительно 30-минутного ориентира SHALL быть третья подряд успешная минутная проверка без изменений, на которой подтверждён полный минимальный комплект. Измерение MUST включать последующее ожидание в очереди и внешние задержки. Система MUST отдельно фиксировать время до `READY`, когда оба PDF проверены и сохранены, и время до первой успешной доставки Telegram-уведомления. Этот ориентир MUST NOT считаться гарантированным SLA первой версии. Длительность MUST измеряться монотонными часами и MUST NOT вычисляться вычитанием отображаемых локальных timestamps.

#### Scenario: Готовность подтверждена
- **WHEN** третья стабильная проверка одновременно подтверждает резюме и запись
- **THEN** система сохраняет её время как начало измерения обработки

#### Scenario: Отчёты готовы до доставки уведомления
- **WHEN** оба PDF проверены и сохранены, но Telegram-доставка ещё не завершена
- **THEN** кандидат получает `READY` и система фиксирует время до готовности отчётов
- **AND** полное время до успешного уведомления продолжает измеряться независимо от статуса кандидата

### Requirement: WF-020 [CONFIRMED] Минимальная машина состояний
Workflow SHALL поддерживать состояния `NEW`, `WAITING_FOR_STABILITY`, `MATERIALS_INCOMPLETE`, `MATERIALS_READY`, `TRANSCRIBING`, `ANALYZING`, `VALIDATING`, `READY` и `FAILED`. `FAILED` MUST сопровождаться этапом сбоя, кодом причины, числом попыток и признаком исчерпания автоматических повторов; отдельные технические причины MUST NOT требовать отдельных верхнеуровневых состояний кандидата.

#### Scenario: Кандидат проходит штатную обработку
- **WHEN** полный стабильный комплект обрабатывается без ошибок
- **THEN** переходы проходят через применимые состояния от `NEW` до `READY`
- **AND** система не пропускает обязательные этапы

#### Scenario: Автоматические повторы исчерпаны
- **WHEN** сбойный этап выполнил все разрешённые OPS-003 попытки
- **THEN** кандидат переходит в `FAILED`
- **AND** причина однозначно определяется по сохранённым этапу и коду

#### Scenario: Обязательный файл невозможно обработать
- **WHEN** присутствующее резюме или запись интервью повреждены, имеют неподдерживаемый формат либо не могут быть разобраны
- **THEN** кандидат переходит в `FAILED` без автоматического повтора
- **AND** система сохраняет файл, этап и код причины, не публикует частичный отчёт или уведомление об успехе и предлагает HR заменить файл

### Requirement: WF-021 [CONFIRMED] Аудит переходов состояния
Для каждого перехода система SHALL сохранять абсолютное время в UTC ISO 8601, причину, номер попытки и техническую ошибку при её наличии. Отображение времени MUST использовать настроенную IANA-зону `Asia/Yekaterinburg` и явное смещение `+05:00`, не изменяя сохранённое значение UTC.

#### Scenario: Этап завершился ошибкой
- **WHEN** кандидат переводится в `FAILED`
- **THEN** запись перехода содержит этап, время, причину, попытку и техническую ошибку

### Requirement: WF-022 [CONFIRMED] Идемпотентность обнаружения
Повторная доставка события или повторное сканирование неизменившейся папки MUST NOT создавать дубликаты кандидата или обработки.

#### Scenario: Один снимок получен повторно
- **WHEN** система повторно обрабатывает то же событие и версии файлов
- **THEN** она связывает событие с существующим объектом
- **AND** не запускает дублирующее задание

### Requirement: WF-023 [CONFIRMED] Безопасный повтор этапов
Ошибочный этап SHALL допускать ограниченный автоматический повтор по OPS-003 и явный ручной повтор HR без повторения уже завершённых дорогостоящих операций, если входные версии не изменились. Если входные версии изменились, ручной запуск MUST следовать правилам новой версии комплекта WF-014.

#### Scenario: AI-анализ повторяется после транскрибации
- **WHEN** анализ завершился ошибкой, а входные файлы и стенограмма неизменны
- **THEN** повтор использует сохранённую стенограмму
- **AND** не отправляет аудио на повторную транскрибацию

#### Scenario: HR повторяет терминально сбойный этап
- **WHEN** кандидат находится в `FAILED`, входные версии не изменились и HR запускает повтор
- **THEN** новый запуск начинается со сбойного этапа
- **AND** сохраняет ссылку на переиспользованные результаты завершённых этапов

#### Scenario: HR заменяет необрабатываемый обязательный файл
- **WHEN** кандидат находится в `FAILED` из-за повреждённого или неподдерживаемого обязательного файла и HR заменяет этот файл
- **THEN** система создаёт новую версию входного комплекта по WF-014
- **AND** после стабилизации полного комплекта HR вручную запускает новый анализ по WF-031

#### Scenario: Повтор после неподдерживаемой AI-схемы
- **WHEN** анализ завершился `UNSUPPORTED_SCHEMA_VERSION`, конфигурация исправлена, а входы, OCR и стенограмма не изменились
- **THEN** ручной повтор начинает AI-анализ заново и выполняет последующие этапы
- **AND** не повторяет извлечение документов, OCR или транскрибацию

### Requirement: WF-030 [CONFIRMED] Последовательность основного процесса
Основной процесс SHALL обнаружить папку или изменение; связать её с вакансией и кандидатом; дождаться стабильности; проверить комплект; зафиксировать версии и SLA; извлечь текст резюме; определить медиаконтейнер по содержимому; получить и проверить стенограмму с говорящими, таймкодами и уверенностью; собрать факты; применить версию профиля; найти риски, стоп-факторы, противоречия и пробелы; проверить согласованность; сохранить отчёт и уведомить HR.

#### Scenario: Полный комплект проходит обработку
- **WHEN** кандидат достигает `MATERIALS_READY`
- **THEN** система выполняет обязательные этапы в указанной зависимости
- **AND** публикует результат только после проверки полноты и согласованности

### Requirement: WF-031 [CONFIRMED] Ручной повтор создаёт новую версию результата
Ручной повторный анализ SHALL использовать последнюю полную и стабильную версию входного комплекта, создавать новый запуск и новую версию результата и MUST NOT удалять или перезаписывать прежнюю.

#### Scenario: HR запускает повторный анализ
- **WHEN** для кандидата уже существует завершённая версия результата
- **THEN** система создаёт новый запуск и новую версию результата
- **AND** связывает запуск с последней полной и стабильной версией входного комплекта
- **AND** прежняя версия остаётся доступной

### Requirement: WF-032 [CONFIRMED] Наблюдаемая очередь обработки
Интерфейс SHALL показывать факт обнаружения кандидата, текущий этап и прошедшее время. Числовой ETA SHALL показываться только при наличии минимум 10 успешных обработок за последние 90 календарных дней с той же версией конфигурации моделей и этапов. Неуспешные и незавершённые запуски MUST исключаться; успешные запуски с повторами и внешними задержками MUST включаться. Транскрибация MUST нормализоваться по длительности записи, OCR — по числу страниц, а для остальных этапов MUST использоваться медианное оставшееся время сопоставимой выборки. Ожидание очереди MUST рассчитываться отдельно по текущей очереди, настроенному параллелизму и историческому времени обслуживания. ETA MUST пересчитываться при переходе этапа, быть явно обозначен как приблизительный и MUST NOT заменять SLA. При недостаточной выборке или изменившейся конфигурации интерфейс MUST вместо числа показывать `Недостаточно данных для прогноза`. Архивирование MUST сохраняться как отдельный обратимый lifecycle-признак, а не заменять последнее состояние обработки. Архивированный кандидат MUST быть скрыт из активной очереди и списков по умолчанию, доступен через фильтр архива и исключён из автоматических запусков и уведомлений. Восстановление MUST возвращать его в применимое предыдущее состояние без автоматического повторного анализа.

#### Scenario: Кандидат обрабатывается
- **WHEN** HR открывает очередь
- **THEN** он видит текущий этап, elapsed time и оценочный ETA при достаточной сопоставимой выборке
- **AND** интерфейс отличает ETA от обязательной SLA-цели

#### Scenario: Истории недостаточно
- **WHEN** для текущей версии конфигурации доступно меньше 10 успешных обработок за последние 90 дней
- **THEN** HR видит текущий этап, прошедшее время и `Недостаточно данных для прогноза`
- **AND** числовой ETA не показывается

#### Scenario: Этап изменился
- **WHEN** обработка переходит на следующий этап и сопоставимая выборка достаточна
- **THEN** ETA пересчитывается по оставшимся этапам, а вклад очереди отображается отдельно

#### Scenario: Кандидат архивирован
- **WHEN** HR архивирует кандидата
- **THEN** он исчезает из активной очереди и доступен через фильтр архива
- **AND** автоматическая обработка и уведомления для него не запускаются

#### Scenario: Кандидат восстановлен
- **WHEN** HR восстанавливает кандидата из архива
- **THEN** система возвращает его в применимое сохранённое состояние
- **AND** не запускает повторный анализ без отдельного триггера
