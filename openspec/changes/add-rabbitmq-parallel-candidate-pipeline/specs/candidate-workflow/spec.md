## ADDED Requirements

### Requirement: WF-040 [CONFIRMED] Изоляция и параллельность кандидатов

Canonical candidate DAG MUST позволять одновременно выполнять независимые runnable-задачи разных кандидатов. Долгая, повторяемая или ошибочная задача одного кандидата MUST NOT удерживать общий последовательный цикл и MUST NOT препятствовать продвижению остальных кандидатов.

#### Scenario: Один кандидат ожидает долгую транскрибацию
- **WHEN** транскрибация первого кандидата ещё не завершена
- **AND** у второго кандидата готовы document или LLM-задачи
- **THEN** второй кандидат продолжает обработку в доступных worker pools

### Requirement: WF-041 [CONFIRMED] Fan-out обработки документов

После фиксации immutable input manifest система MUST создать отдельную детерминированную shard-задачу для каждого поддерживаемого документа, который требует извлечения. Document join MUST завершиться только после terminal success всех обязательных document shards и MUST выдать один канонический набор извлечённых источников без дубликатов.

#### Scenario: У кандидата несколько документов
- **WHEN** manifest содержит резюме, рекомендации и дополнительный документ
- **THEN** документы могут извлекаться параллельно
- **AND** join включает результат каждого source ID ровно один раз
- **AND** downstream evidence не запускается до успешного join

### Requirement: WF-042 [CONFIRMED] Fan-out нескольких интервью

Для каждой записи интервью из immutable manifest система MUST создать независимую ветвь подготовки и транскрибации. Готовая текстовая стенограмма MUST обрабатываться как самостоятельный источник без ожидания media extraction. Transcript join MUST сохранить порядок и идентичность всех интервью и не смешивать таймкоды разных источников.

#### Scenario: Две записи и одна готовая стенограмма
- **WHEN** у кандидата присутствуют две записи интервью и один текстовый transcript
- **THEN** записи транскрибируются независимо и могут выполняться параллельно
- **AND** готовый transcript проходит собственной короткой ветвью
- **AND** join публикует три различимых источника с их source ID

### Requirement: WF-043 [CONFIRMED] Fan-out поиска доказательств по token batches

После готовности нормализованных материалов система MUST построить детерминированный план token batches для frozen matrix и immutable source set. Каждый batch MUST проверять явно назначенный набор критериев и фрагментов; shards MAY выполняться параллельно. Evidence join MUST проверить покрытие каждого запланированного критерия, объединить доказательства по устойчивым идентификаторам, удалить точные дубликаты и сохранить точные ссылки на источник.

#### Scenario: Evidence batches завершаются в другом порядке
- **WHEN** поздний batch завершился раньше первого
- **THEN** join формирует один и тот же канонически упорядоченный результат независимо от порядка завершения
- **AND** ни один критерий из плана не пропускается
- **AND** противоречащие доказательства сохраняются раздельно, а не перезаписывают друг друга

### Requirement: WF-044 [CONFIRMED] Параллельные ABC и первичная оценка строк

После evidence join система MUST независимо запускать ABC-анализ и первичную оценку всех строк матрицы. Первичная оценка строк MUST быть разделена на детерминированные shards с exact row coverage. Recommendation branch MUST ожидать join ABC и join строк.

#### Scenario: ABC готов раньше строк матрицы
- **WHEN** ABC-анализ завершён, но часть row shards ещё выполняется
- **THEN** recommendation не запускается
- **AND** другие row shards продолжают выполнение
- **AND** после обоих join используются результаты одной версии матрицы и evidence

### Requirement: WF-045 [CONFIRMED] Параллельная проверка критических строк

После первичной оценки система MUST определить набор строк, требующих критической проверки, и создать по ним отдельные детерминированные shard-задачи. Нулевой набор MUST завершать join без LLM-вызова. Critical join MUST применить не более одного канонического результата на строку и сохранить исходную оценку для аудита.

#### Scenario: Проверяются несколько критических строк
- **WHEN** три строки требуют критической проверки
- **THEN** три проверки могут выполняться параллельно
- **AND** ошибка одной проверки не изменяет молча остальные строки
- **AND** recommendation запускается только после terminal результата critical join

### Requirement: WF-046 [CONFIRMED] Полный join перед итогом

Итоговая рекомендация, валидация, отчёт и уведомление MUST строиться только из одной согласованной версии manifest, vacancy matrix, evidence joins, ABC join, row join и critical join. Частичный fan-out результат MUST NOT публиковаться как готовый анализ.

#### Scenario: Один обязательный shard отсутствует
- **WHEN** join обнаруживает отсутствующий или неуспешный обязательный shard
- **THEN** downstream итог не становится runnable
- **AND** запуск получает понятный этап и безопасную причину ожидания или ошибки
- **AND** уже успешные shards сохраняются как checkpoints для selective recovery
